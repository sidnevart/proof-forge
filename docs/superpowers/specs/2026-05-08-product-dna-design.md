## Раздел 1. Душа продукта

### Что такое ProofForge

ProofForge — платформа доказуемого прогресса. Не трекер привычек. Не HR-система. Не публичный рейтинг.

**Формула продукта:**
```
цель / инициатива → ритм → proof contract → proof → buddy seal → growth dossier
```

**Главная сущность** — не задача и не сезон, а **proof contract**: конкретное обещание показать доказательство прогресса к определённому моменту.

### Пять тезисов позиционирования

1. **Публично — вклад.** Платформа показывает что ты сделал, не где ты стоишь в рейтинге.
2. **Приватно — риски.** То, что человек застрял или отстаёт, видит только он сам и тот, кто помогает.
3. **Сравнение с собой вчерашним.** Не с лидером, не с коллегой — с собственным прошлым результатом.
4. **Buddy = поддержка, не контроль.** Buddy помогает не слиться, а не следит и не оценивает.
5. **AI работает на пользователя, не на руководителя.** Личный контекст по умолчанию виден только самому пользователю.

### Чего ProofForge НЕ делает

- Не ведёт обязательные рабочие задачи (это Jira/YouTrack)
- Не показывает публично "худшего участника"
- Не даёт AI финальное решение вместо человека
- Не превращается в инструмент давления руководителя
- Не требует длинных анкет при старте

### Позиция относительно других инструментов

- **До Jira** — когда команда исследует идею и собирает доказательства что её стоит делать
- **Рядом с Jira** — когда сотрудник использует рабочий артефакт как пруф развития
- **Не вместо Jira** — управление обязательным исполнением задач остаётся там

## Раздел 2. Дизайн-принципы

### П1. Proof-first

Каждый экран ведёт к сдаче пруфа, отображает прогресс пруфа или отмечает завершённый пруф. Если экран не делает ни одного из трёх — он лишний.

**На практике:** кнопка CTA на дашборде всегда связана с пруфом. Лидерские дашборды показывают пруфы, не абстрактные "активность".

### П2. Контекст вместо инструкций

Платформа не объясняет что делать — она показывает следующее действие исходя из текущего состояния пользователя.

**На практике:** умная карточка "Что сейчас" — единственный источник направления на дашборде. Пустые состояния всегда содержат конкретное следующее действие, не просто "здесь пока ничего нет".

### П3. Одно действие за один момент

На каждом экране максимум одно primary CTA. Остальные действия — secondary или скрыты в меню.

**На практике:** нет экранов с двумя одинаково весомыми кнопками. Если есть выбор — сначала показываем рекомендованный вариант.

### П4. Прогрессивное раскрытие

Простой путь по умолчанию. Сложный — по запросу. Новый пользователь не должен видеть advanced-настройки пока они ему не нужны.

**На практике:** форма создания цели — одно поле на старте. Wizard настройки space — 6 шагов с пресетами, не с полями. Advanced-параметры за кнопкой "Настроить подробнее".

### П5. Публично вклад, приватно риски

Борды и витрины показывают достижения и артефакты. Проблемы ("кто застрял", "кто не сдавал 2 недели") — только приватно лидеру.

**На практике:** нет публичного ранжирования от первого до последнего. Нет публичных меток "отстающий". Борд стабильности показывает топ, не дно.

### П6. Тёмный брутализм = намеренная красота

Чёрный фон, острые углы, Display-шрифт, монохром с яркими акцентами — это не аскетизм, это эстетическое решение. Красота достигается через типографику, ритм и контраст, а не через декор.

**На практике:** никаких теней, градиентов, иллюстраций или иконок-стикеров. Если нужно выделить элемент — используй цветной border или акцентный цвет текста.

### П7. AI как тихий советник

AI появляется только в точках где он реально полезен: создание цели, застревание, перед отправкой пруфа, сборка досье. В остальное время — невидим.

**На практике:** нет постоянного AI-чата. Нет AI-баннеров. Есть кнопки "Предложить 3 пруфа", "Проверить перед отправкой", "Я застрял" — точечно в нужных флоу.

### П8. Социальность без давления

Люди видят друг друга через пруфы и вклад, но не через ранги. Сравнение мягкое и opt-in.

**На практике:** витрина лучших пруфов — про артефакты. Борд кругов — про командный результат. Личный прогресс — всегда главнее публичного.

### П9. Скорость над полнотой

Первый пруф — за 2 минуты. Настройка space — за 20 секунд. Если флоу требует больше — он сломан.

**На практике:** измеряем время завершения ключевых флоу. Если требуется больше 3 нажатий для основного действия — редизайн.

### П10. Необратимые действия защищены

Удаление, архивация, заморозка пространства, снятие роли — требуют явного подтверждения с описанием последствий. Нет "удалить" без "вы уверены? это нельзя отменить".

**На практике:** destructive actions — красная кнопка с модальным подтверждением. Минимум для подтверждения: заголовок, описание последствий, две кнопки (отмена и подтверждение).

## Раздел 3. Визуальная система

### Цветовые токены

Используются существующие CSS-переменные из `web/app/globals.css`. Не добавлять новые без необходимости.

```css
/* Фоны — от самого тёмного к светлому */
--bg-base: #000000       /* страница, полный чёрный */
--bg-surface: #0a0a0a    /* карточки, панели */
--bg-elevated: #141414   /* инпуты, вложенные поверхности */

/* Текст */
--ink-primary: #ffffff   /* основной текст */
--ink-mono: #a0a0a0      /* вторичный, подписи */

/* Акценты — использовать со смыслом */
--win: #1ce783           /* успех, подтверждение, активно */
--fire: #ff7a1a          /* предупреждение, дедлайн скоро */
--warn: #ffb01f          /* ожидание, pending */
--danger: #ff2a2a        /* ошибка, destructive action */
--frost: #9fdfff         /* AI, информация, нейтральный акцент */

/* Границы */
--border: #1f1f1f        /* разделители */
--border-strong: #2a2a2a /* выделенные границы */
```

### Семантика цветов

| Цвет | Когда использовать | Нельзя использовать для |
|------|-------------------|------------------------|
| `--win` (зелёный) | Успех, подтверждение, активный статус, CTA | Предупреждения |
| `--fire` (оранжевый) | Дедлайн приближается (< 2 дней), горящее действие | Ошибки |
| `--warn` (жёлтый) | Ожидание ревью, pending статус | Успех |
| `--danger` (красный) | Ошибка, destructive action, overdue | Предупреждения |
| `--frost` (голубой) | AI-подсказки, информационные блоки | Статусы успеха/ошибки |

### Типографика

```css
--font-display: "Impact", "Arial Black", sans-serif  /* заголовки экранов */
--font-body: "Helvetica Neue", "Arial", sans-serif   /* основной текст */
--font-mono: "Courier New", monospace                /* eyebrow-labels, meta */
```

**Шкала размеров:**

| Элемент | Размер | Шрифт | Вес | Особенности |
|---------|--------|-------|-----|-------------|
| Screen title | clamp(28px, 5vw, 48px) | display | 700 | uppercase |
| Section heading | clamp(18px, 3vw, 24px) | display | 700 | — |
| Eyebrow label | 10–11px | mono | 700 | uppercase, letter-spacing: 0.12em |
| Body text | 14–15px | body | 400 | line-height: 1.5 |
| Secondary text | 12–13px | body | 400 | color: --ink-mono |
| Button text | 12px | body | 700 | uppercase, letter-spacing: 0.1em |
| Status pill | 10px | mono | 700 | uppercase |

### Отступы

Использовать эту шкалу, не произвольные значения:

```
4px   — между иконкой и текстом
8px   — внутри pill/badge
12px  — между элементами внутри карточки
16px  — padding карточки (mobile)
20px  — padding карточки (desktop)
24px  — между карточками
32px  — между секциями
48px  — между крупными блоками
```

### Форма элементов

- **Border-radius: 0** — для карточек, кнопок, инпутов (sharp = намеренно)
- **Border-radius: 2px** — только для status pill и маленьких badge
- **Border-radius: 50%** — только для аватаров пользователей
- Никаких box-shadow на тёмном фоне (не работают визуально)

### Акцентная граница

Использовать `border-left: 3px solid {цвет}` для визуального выделения карточки без фонового цвета. Примеры:
- Активная цель → `border-left: 3px solid var(--win)`
- AI-подсказка → `border-left: 3px solid var(--frost)`
- Срочное → `border-left: 3px solid var(--fire)`

### Анимации

**Разрешено:**
- `transition: 140ms ease` — для hover states кнопок
- `opacity` fade для появления/исчезновения элементов (200ms)
- Pulse для "нужна реакция" индикаторов (1.5s loop, opacity 0.6→1)

**Запрещено:**
- Сложные keyframe-анимации для основных UI-элементов
- Parallax и scroll-triggered animations
- Bounce, elastic эффекты
- Анимации длиннее 400ms для интерактивных элементов

## Раздел 4. UX-паттерны «платформа понимает тебя»

### Умная карточка «Что сейчас»

Главная карточка на дашборде. Всегда показывает **одно** наиболее релевантное действие. Алгоритм выбора (приоритет сверху вниз):

```
1. Бадди ждёт ответа > 24 часов        → "Ответь бадди — [имя] ждёт N день"
2. Proof contract просрочен              → "Пруф просрочен — сдай сейчас или обнови контракт"
3. Дедлайн proof contract сегодня       → "Дедлайн сегодня — [цель]"
4. Дедлайн proof contract завтра        → "Дедлайн завтра — [цель]"
5. Нет пруфа 5+ дней (regular rhythm)   → "Ты не сдавал пруф 5 дней — следующий шаг: [AI шаг]"
6. Нет пруфа 3 дня (regular rhythm)     → "Небольшой перерыв — готов к следующему шагу?"
7. Есть достижение для отмечания        → "[Milestone] — ты завершил [N]"
8. Нет активных целей                   → "Начни — создай первую цель или подключись к инициативе"
9. Всё хорошо                           → "Всё идёт по плану. Следующий пруф: [дата]"
```

**Структура карточки:**
```
[EYEBROW LABEL — контекст ситуации]
[ЗАГОЛОВОК — суть одним предложением]  
[ПОДЗАГОЛОВОК — детали или следующий шаг]
[→ CTA КНОПКА — одно действие]
```

**Цветовая граница карточки** отражает состояние:
- Срочное/просрочено → `--danger`
- Дедлайн скоро → `--fire`
- Ожидание от бадди → `--warn`
- Достижение → `--win`
- Нейтральное → `--border`

### Progressive Disclosure

**Правило:** показывать минимум полей/опций на старте, расширять по запросу.

**Паттерн для форм:**
1. Первый экран — 1–2 поля (самые важные)
2. После заполнения → появляются следующие поля
3. Advanced-опции за явной кнопкой "Подробнее" или "Настроить"
4. Defaults всегда умные (лучший вариант для 80% случаев)

**Паттерн для wizard:**
1. Каждый шаг — одно решение
2. Пресеты — кликабельные карточки, не dropdown
3. Шаг пропускаем если есть очевидный default
4. "Пропустить" всегда доступен для необязательных шагов

### Empty States

Каждое пустое состояние должно содержать:
```
[Краткое объяснение почему пусто — 1 строка]
[→ Конкретное действие для заполнения]
```

Примеры:
- Нет целей → "Добавь первую цель и получи buddy → [Создать цель]"
- Нет пруфов → "Сдай первый пруф по цели → [Сдать пруф]"
- Нет бадди → "Пригласи бадди — он поможет не слиться → [Пригласить]"
- Лидерборд пуст → "Сезон только начался — первые пруфы появятся здесь"

Никогда: "Здесь пока ничего нет" без действия.

### Confirmation Moments

Когда пользователь совершает значимое действие — платформа отвечает.

**Типы реакций:**

| Событие | Реакция |
|---------|---------|
| Сдан пруф | Полноэкранный момент успеха: "[eyebrow] ПРУФ СДАН / [заголовок] Отличная работа / [детали] Buddy получил уведомление" |
| Buddy подтвердил | Уведомление с именем buddy и его комментарием |
| Завершена цель | Milestone-экран с предложением создать dosier |
| Первый пруф | Особое поздравление + "теперь настрой регулярный ритм" |
| Streak продолжается | Тихое но заметное "🔥 7 недель подряд" в личном борде |

### Деструктивные действия

Паттерн подтверждения для любого необратимого действия:

```
Modal:
  [Заголовок] "Удалить [объект]?"
  [Описание] "Это удалит [что именно]. Отменить нельзя."
  [Кнопки] [Отмена] [--danger: Удалить]
```

Никогда: inline кнопка "удалить" без подтверждения.

## Раздел 5. Мобайл: правила и паттерны

### Safe Area и Layout

```css
/* Всегда учитывать safe areas */
padding-bottom: env(safe-area-inset-bottom);
padding-top: env(safe-area-inset-top);

/* Bottom nav — фиксированный, поверх контента */
position: fixed;
bottom: 0;
padding-bottom: calc(8px + env(safe-area-inset-bottom));
```

### Thumb Zone Map

Экран смартфона разделён на зоны досягаемости большого пальца:

```
┌─────────────────┐
│   СЛОЖНО (20%)  │  ← Заголовки, вторичная информация
│                 │
│   НОРМАЛЬНО     │  ← Карточки, списки, контент
│     (50%)       │
│                 │
│   ЛЕГКО (30%)   │  ← Primary CTA, Tab Bar
└─────────────────┘
```

**Правило:** Primary CTA кнопка всегда в нижней трети экрана на мобайле. Опасные действия — вверху (требуют усилия).

### Touch Targets

- Минимум 48×48px для всех интерактивных элементов
- Между touch targets минимум 8px gap
- Текстовые ссылки в body-тексте — не используем (только кнопки)

### Bottom Sheet вместо Modal

На мобайле модальные окна заменяются bottom sheet:
```
- Появляется снизу (slide up animation 280ms)
- Можно закрыть свайпом вниз
- Handle indicator сверху (32×4px, --border-strong)
- Max height: 90vh
- Backdrop: rgba(0,0,0,0.6)
```

Модальное окно оставляем только для destructive confirmation (они должны требовать осознанного нажатия, не случайного).

### Swipe Actions на карточках

Для списков (очередь бадди, proof contracts, уведомления):
- Swipe right → primary action (подтвердить, принять)
- Swipe left → secondary/destructive (отклонить, удалить)
- Reveal color: right → `--win`, left → `--danger`
- Trigger на 40% ширины карточки

### Навигация

**Bottom Tab Bar (mobile, ≤ 640px):**
```
[Главная] [Пруфы] [Сообщество] [Я]
```
- Активная вкладка: белый цвет + underline `--win`
- Неактивная: `--ink-mono`
- Badge для уведомлений: красная точка, не число (если > 9 → "9+")
- Glassmorphic backdrop: `backdrop-filter: blur(12px)`

**Нет hamburger меню на мобайле.** Всё доступно через Tab Bar или bottom sheet.

### Pull-to-Refresh

На feed-экранах и дашборде. Threshold: 64px. Indicator: `--win` цвет.

### Haptic Feedback (веб-вибрация)

```javascript
// Лёгкий тап при выборе
navigator.vibrate(10);

// Успех (пруф сдан)
navigator.vibrate([15, 50, 15]);

// Ошибка
navigator.vibrate([50, 30, 50]);
```

Использовать только для значимых событий, не для каждого клика.

## Раздел 6. Десктоп: правила и паттерны

### Навигация

**Sidebar (desktop, > 640px):**
```
[Лого]
──────────
[Главная]
[Мои цели]
[Сообщество]
──────────
[Лидерские view — только если есть роль]
  [Мой Teamspace]
  [Аналитика]
──────────
[Настройки]
[Профиль]
```
- Ширина: 220px фиксированная
- Collapsed: 60px (только иконки) — опционально для admin views
- Активный пункт: `--win` border-left 3px

### Hover States

```css
/* Карточки */
.card:hover {
  border-color: var(--border-strong);
  transition: border-color 140ms ease;
}

/* Кнопки */
.btn-primary:hover {
  background: var(--ink-mono);
  transition: background 140ms ease;
}

/* Ссылки в меню */
.nav-item:hover {
  color: var(--ink-primary);
}
```

Никогда: transform: scale() на hover (ощущается как игрушка).

### Keyboard Shortcuts

Обязательные для лидерских и admin views:

| Shortcut | Действие |
|----------|----------|
| `N` | Новый proof contract / новая цель |
| `R` | Refresh / reload данных |
| `Esc` | Закрыть modal/bottom sheet |
| `Enter` | Подтвердить primary action |
| `↑↓` | Навигация по списку |

### Многоколоночные Layouts

Используем только когда данные требуют сравнения:
- Лидерборды → таблица или 2-col grid
- Аналитика тимлида → 3-4 stat card в ряд
- Admin panel → sidebar + main content split
- Buddy review → split view (пруф слева, форма ревью справа)

**Никогда:** многоколоночный layout для форм ввода (всегда single column).

### Max-Width и Центровка

```css
.page-shell {
  max-width: 1240px;
  margin: 0 auto;
  padding: 0 clamp(20px, 3vw, 48px);
}

/* Контент страниц (не admin) */
.content-shell {
  max-width: 720px;
  margin: 0 auto;
}

/* Admin и аналитика */
.admin-shell {
  max-width: 1100px;
  margin: 0 auto;
}
```

## Раздел 7. Технические ограничения и паттерны

### CSS Modules — обязательно

**Не использовать:** Tailwind, Styled Components, Emotion, inline styles (кроме динамических значений).

**Структура файлов:**
```
ComponentName/
  index.tsx          ← компонент
  ComponentName.module.css  ← стили
```

или для простых компонентов:
```
component-name.tsx
component-name.module.css
```

**Именование классов в CSS Modules:**
```css
/* camelCase для классов */
.cardContainer { }
.titleText { }
.primaryBtn { }

/* НЕ BEM, не kebab-case */
```

### Container Queries

Использовать для компонентов которые меняют layout в зависимости от своего контейнера (не viewport):

```css
.cardWrapper {
  container-type: inline-size;
}

@container (min-width: 400px) {
  .card { flex-direction: row; }
}
```

Особенно важно для: goal-circle-card, proof-card, leaderboard-row.

### Responsive Typography

Все заголовки через `clamp()`:
```css
font-size: clamp(MIN, PREFERRED, MAX);

/* Примеры */
font-size: clamp(24px, 4vw, 40px);  /* section title */
font-size: clamp(14px, 2vw, 16px);  /* body */
```

### Структура Go Backend API

Все новые endpoint'ы следуют паттерну:

```
POST   /v1/{resource}              ← create
GET    /v1/{resource}              ← list
GET    /v1/{resource}/{id}         ← get by id  
PATCH  /v1/{resource}/{id}         ← update
DELETE /v1/{resource}/{id}         ← delete/archive

POST   /v1/{resource}/{id}/{action} ← специфические действия
```

**Ответы API:**
```json
// Успех
{ "data": { ... } }

// Список
{ "data": [ ... ], "meta": { "total": N } }

// Ошибка
{ "error": { "code": "...", "message": "..." } }
```

**Роли в JWT:** `platform_admin`, `workspace_owner`, `community_leader`, `teamspace_lead`, `trusted_approver`, `member`, `buddy`
